# `jekyll` 站点档案（Jekyll · 图鉴扩展位）

- **预留子模块路径**：`sites/jekyll`（与本档案 `docs/sites/jekyll.md` 严格 1:1 对应）
- **上游官方仓库**：[`jekyll/jekyll`](https://github.com/jekyll/jekyll)
- **底层技术栈**：Ruby + Kramdown 解析器 + Liquid 模板

## 1. 生命周期定位（开始 / 活跃 / 废弃时间）

| 指标 | 时间节点与演进状态 |
| :--- | :--- |
| **开始时间** | **`2008-10-20`** 由 GitHub 联合创始人 Tom Preston-Werner 创立，开创“静态网站生成器（SSG）”概念 |
| **活跃时间** | **`2009–2017` 为全球统治黄金期**（`2014` 年创下惊人的单年 `2,144` 次提交峰值）；`2021` 起逐年递减至 `2026` 年仅 `24` 次提交 |
| **废弃 / 演进状态** | **核心未正式归档废弃**（作为 GitHub Pages 历史默认引擎保留），但在**现代新建技术文档站选型中已事实退场** |

## 3. 历史贡献与 `.nojekyll` 溯源

1. **为什么现代框架都要放 `.nojekyll`？**：GitHub Pages 默认用 Jekyll 处理分支，而 Jekyll 将一切以下划线 `_` 开头的路径（如 `_posts`、`_layouts`）视为私有编译源码而非静态资源——这导致 Astro 的 `/_astro/` 产物目录与 Docsify 的 `_sidebar.md` 若不加 `.nojekyll` 空文件关停 Jekyll，就会在线上全部 404！
2. **现代局限**：面向日期归档博客设计，Ruby 本地环境在非 Ruby 团队维护成本高，且 Kramdown `{: .warning }` 方言无法跨生态迁移。
